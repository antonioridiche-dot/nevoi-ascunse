## Program central de afiliere

Portalul central este activ la `/afiliere`, cu reguli publice, materiale marcate explicit **„În lucru”**, înscriere deschisă, dashboard de afiliat și zona administrativă `/afiliere/admin`. Linkul canonic este `/afiliere/<oferta>/<cod>`; acesta validează afiliatul și oferta, persistă atribuirea de 30 de zile în server și redirecționează la ruta directă a brandului.

Regula curentă este 50% din baza de comision server-side, cu maturizare de 30 de zile complete, prag de 100 RON și batch administrativ la 1 și 15 ale lunii. Payouturile v1 sunt limitate explicit la RON, nu sunt inițiate automat și nu folosesc Stripe Connect. La prima cerere se colectează profilul de payout; un administrator verifică profilul, aprobă cererea și poate marca plata doar cu o referință bancară. Ledgerul are stări pentru pending, eligible, paid, reversed și chargeback adjustment; reversarea este disponibilă administrativ pentru refund/chargeback.

Integrarea afiliată este conectată la checkout/fulfillment pentru Tarot, Familie protejată, Prieteni cu beneficii, Vrăji, Weightloss, Relații, Armonii & Bine, Iubire, Liniște Audio și Calendarul norocului. Prieteni cu beneficii păstrează obligatoriu Stripe Checkout extern; după o sesiune plătită, serverul materializează comanda, drepturile și ledgerul fără a schimba checkoutul hosted. Webhookul Stripe include acum reversare idempotentă numai pentru un `refund.updated` reușit care acoperă integral charge-ul și pentru un `charge.dispute.closed` pierdut care acoperă integral charge-ul. Endpointul Stripe sandbox este configurat spre domeniul public și alege evenimentele de checkout, refund și dispută necesare; răspunsul endpointului a fost verificat pentru payloaduri test semnate local, dar o livrare inițiată de Stripe și reconcilierea reală DB/ledger rămân nevalidate. Refundurile sau disputele parțiale nu sunt automatizate până la modelarea ajustărilor proporționale, iar recuperarea automată a unui comision deja plătit nu este implementată. Nu este declarată încă paritatea end-to-end pentru upsellurile, downsellurile sau rutele neportate. Autentificarea prin cod este implementată, dar livrarea codului nu poate fi declarată funcțională până la verificarea expeditorului Resend `nevoi-ascunse.ro`.

## Copy-First Regression Rule

Each route is accepted only after these conditions are met:

1. The source file and unified file have the same customer-facing structure, copy, prices, CTA order, checkout type, and post-payment navigation.
2. Any difference is documented as only one of: unified route prefix, typed server contract, unified database relation, or shared secure storage/email adapter.
3. The server validates products and amounts, Stripe confirms payment, the source-equivalent post-payment path completes, and protected access is granted only after the confirmed order.
4. Source assets are used only when present in the repository or approved storage. Missing assets remain documented and are never replaced with invented media.
